# gitback2life — Operating Checklist

## Before publishing

- [ ] Is every factual claim true?
- [ ] Does the post follow the platform's current rules?
- [ ] Is any identifying information exposed?
- [ ] Is the material intentionally public?
- [ ] Does it contain sensitive financial, medical, account, legal, or private information?
- [ ] Is the support request specific without creating pressure?
- [ ] Is the requested support method legitimate and current?
- [ ] Is the post useful even to someone who does not contribute?

## Before committing to the public repository

- [ ] Treat the repository as permanently public.
- [ ] Check for credentials, tokens, passwords, private URLs, and local paths.
- [ ] Check screenshots and images for notifications, account names, email addresses, addresses, or other identifying details.
- [ ] Check documents for private research, correspondence, financial information, and sensitive personal context.
- [ ] Confirm that any research note is deliberately selected for public documentation and sanitized.
- [ ] Prefer a private workspace when material is not intentionally public.

## Before accepting support

- [ ] Verify the method against official provider instructions.
- [ ] Never publish a PIN, claim link, password, or recovery code.
- [ ] Do not pay anyone to receive support.
- [ ] Do not accept funds that require forwarding or laundering money.

## After support

- [ ] Confirm receipt safely.
- [ ] Record only public-safe project impact.
- [ ] Keep private financial/accounting records outside the public repository.
- [ ] Document concrete work completed.
- [ ] Avoid implying guaranteed outcomes.
- [ ] Reassess whether outside support is still necessary.
