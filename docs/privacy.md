# gitback2life — Privacy & Public Repository Rules

## Public identity
Use only the project identity **gitback2life** and the dedicated project email for public-facing activity.

The repository is intentionally public. Treat anything committed here as potentially visible to anyone and preserved in public Git history.

## Never publish
- legal name
- home address
- personal phone number
- personal email address
- medical records or disability documents
- government identification
- bank/card/account numbers
- passwords or recovery codes
- API keys, access tokens, private keys, or credentials
- private gift-card PINs, claim links, or redemption codes
- private account identifiers
- private correspondence
- identifying photographs unless deliberately reviewed for privacy
- sensitive personal records
- private research or internal notes that are not intentionally part of the public project

## Public-repository rule

Before committing anything, ask:

1. Is this intentionally part of the public gitback2life project?
2. Could it identify the person behind the project?
3. Does it contain sensitive personal, financial, medical, account, or security information?
4. Is it private correspondence or an internal working note?
5. Would exposing it create a problem even if the file were later deleted?
6. Is there a safer way to document the same lesson without exposing unnecessary information?

If the answer to questions 2–5 raises concern, do not commit the material to this repository.

## Private work belongs elsewhere

Detailed private research, personal records, account information, unpublished operational notes, credentials, and other sensitive material should be kept in a private workspace or private repository.

The public repository may contain a sanitized conclusion or a deliberately public research note when that material is genuinely part of the project.

A file being useful to an AI session does not make it appropriate for the public repository.

## Git history matters

Deleting a sensitive file from the current version does not necessarily remove it from public Git history.

If a real credential or sensitive identifying information is ever committed, treat it as exposed: revoke/rotate credentials as appropriate and assess whether the historical exposure needs remediation.

## Important distinction

Privacy means protecting the real person's identity and sensitive information; it does not mean inventing false facts.

If a platform, employer, payment provider, or government service legally requires identity verification, provide accurate information privately through that service.

## AI/session rule

AI-assisted sessions must apply these rules before creating or updating public repository files.

The session handoff and research-session starter are public-safe project workflow documents. They must not become containers for private personal context.

## Research rule

Research is not automatically public.

Detailed research that is not intentionally part of the public project should stay in a private research workspace. Only research deliberately selected for public documentation should enter this repository.

## Public-project principle

The public repository is the public project.

**If it is committed here, assume the world can see it.**
