# Ideas, Suggestions, and Requests

gitback2life is being built in public, which means other people can help shape what gets built next.

## Public route

The preferred route for ideas and build requests is the GitHub issue forms:

- **Suggest an Idea** — suggest something to learn, investigate, improve, or build.
- **Request a Build** — ask for a practical experiment, small tool, explanation, or challenge.

This keeps useful feedback visible, searchable, and potentially reusable as part of the project's build history.

## Privacy

GitHub issues are public. People who submit them should not post real names, home addresses, phone numbers, medical records, financial information, passwords, or other private details.

The project is pseudonymous. A public contributor may still be identifiable through their GitHub account, so contributors should use whatever level of public identity they are comfortable with.

## How requests are handled

A suggestion is not automatically a promise to build something.

The project will consider requests based on:

1. whether the request fits the rebuild/learn/build/independence mission;
2. whether it can be explored safely and legally;
3. whether it can be done at $0 upfront cost when possible;
4. whether it teaches something useful or produces a meaningful artifact;
5. whether the result can be documented honestly.

A useful request may become a build, experiment, case study, research note, or future backlog item.

## Why this matters

The project is not only a diary. It is also an experiment in using AI, public feedback, and real-world problems to decide what to learn and build next.

**A good idea can become the next line of code.**
